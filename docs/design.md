# Basket Score 1.0 設計書

- 版: 第1版（2026-11-12）
- 元にする要件: [requirements.md](requirements.md)（第3版）
- 範囲: 1.0（タブレットだけで動く記録と分析）。1.1 以降は、1.0 を使ってから設計する

## 1. 全体の作り

| 層 | 場所 | 中身 | Android に依存するか |
| --- | --- | --- | --- |
| 規則と計算 | `rules/`・`game/`・`stats/` | 試合の規則、記録（出来事）の型、出来事の並びから試合の状態を作る計算、スコアシートの中身、スタッツと分析の計算 | しない（純粋な Kotlin。単体テストで確かめる） |
| データ | `data/` | Room（端末の中のデータベース）。チーム・選手・試合・出来事・変更の履歴 | する |
| 出力 | `pdf/`・`export/` | スコアシートと分析の PDF（`PdfDocument` に Canvas で描く）、CSV、バックアップ | する |
| 画面 | `ui/` | Jetpack Compose の画面と ViewModel | する |

**記録は「出来事の並び」として持つ。** 得点・ファウル・交代などを 1 件ずつ保存し、スコアシート・ファウルの数・スタッツ・分析は、すべてこの並びから毎回計算する（要件 9 章）。

- 取り消し・修正・差し込みは、出来事を消す・書き換える・間に入れるだけ。計算し直せば、ランニングスコアもファウルの数も食い違わない
- 1 試合の出来事は多くて 1500 件ほどなので、操作のたびに最初から計算し直しても速い（数ミリ秒）。途中の結果をため込む工夫は、遅いと分かってから入れる
- 動画との連動（3.0）やクラウドへの送信（2.0）も、この並びをそのまま使う

## 2. データ

### 2.1 Room の表

| 表 | 主な列 | 備考 |
| --- | --- | --- |
| `team` | id・名前・略称・濃色・淡色・ヘッドコーチ・A.コーチ（氏名と登録番号）・作成日時 | チームのコピー（F-105）は行と選手を複製する |
| `player` | id・team_id・背番号（文字列。"0"〜"99" と "00"）・氏名・登録番号（下 3 桁）・キャプテン・ポジション・並び順・削除済み | |
| `folder` | id・名前・作成日時 | 大会のフォルダ（F-1007。データベースの版 3 で追加） |
| `game` | id・状態（準備・試合中・終了・確定）・試合の設定（JSON）・作成日時・更新日時・最終スコア（一覧用の写し）・folder_id（大会のフォルダ。null なら未分類） | 試合の設定は 2.2。folder_id に外部キーは付けない（6 章） |
| `game_event` | id・game_id・順番（seq）・ピリオド・ゲームクロックの残り（ミリ秒、時計を使わないときは null）・出来事（JSON）・作成日時 | 順番は差し込みのために間を空けて振る（1000 刻み）|
| `edit_history` | id・game_id・日時・操作（追加・変更・削除）・対象（出来事・選手・チーム・試合の情報）・前・後（JSON） | 更新履歴（F-313） |

### 2.2 試合の設定（`GameSetup`、JSON で `game` に入れる）

- ヘッダー: 大会名・日付・開始時刻・会場・ゲーム番号
- 審判（クルーチーフ・アンパイア 1・2）と TO の氏名
- 区分と規則（`GameRules`）、記録の詳しさ、チームごとにスタッツを記録するか、時計を使うか
- チーム A・B: 名前・色・ベンチの位置（左右）・コーチ・A.コーチ・**出場登録選手の写し**（背番号・氏名・登録番号・キャプテン・スターター。試合の中で使う ID を振る）

選手は写しを持つ。あとで名簿を直しても、終わった試合のスコアシートは変わらない。

### 2.3 出来事の型（`GameEvent`）

すべての出来事は「ピリオド」と「ゲームクロックの残り（任意）」を持つ。チームは A・B、選手は試合の中の ID で指す。

| 型 | 中身 | 公式の欄 | スタッツ |
| --- | --- | --- | --- |
| `PeriodStart` / `PeriodEnd` | ピリオドの番号 | クォーターの終わりの○と線 | 時間帯の区切り |
| `Shot` | チーム・選手・種類（FT・2P・3P）・成否・位置（コートの図の座標、任意）・シュートの種別・アシスト・ブロック | 成功したものが得点（ランニングスコア） | 試投・成功・シュートチャート |
| `Foul` | チーム・誰に（選手・ヘッドコーチ・ベンチ）・記号（P・T・U・D・C・B・M）・フリースローの数・相殺（c）・ファウルを受けた選手（任意） | ファウルの欄・チームファウル | ファウル |
| `Timeout` | チーム | タイムアウトの欄（経過時間の分） | 時間帯 |
| `Substitution` | 交代の組（チーム・出る選手・入る選手）の並び。両チームを 1 件でまとめて記録できる（F-308） | 出場（Player in）の欄 | 出場時間・ラインナップ |
| `JumpBallSituation` | — | ポゼッションアローを反転する | 攻守の交代 |
| `ArrowSet` | 向き（試合の初めに決める） | アロー | — |
| `Rebound` | チーム・選手（null ならチームリバウンド）・オフェンスかディフェンスか | — | REB |
| `Turnover` | チーム・選手（任意）・種類・スティールした相手の選手（任意） | — | TO・STL |
| `Deflection` | チーム・選手 | — | ディフレクション |
| `PossessionChange` | 新しく攻めるチーム | — | 自動で判断できない攻守の交代を直す（F-411） |
| `GameEnd` | 終了時刻 | 最終結果 | — |

### 2.4 試合の状態（`GameState`）

出来事の並びを先頭から順に適用して作る。

- 今のピリオド、得点、ランニングスコア（1 点ごとの欄: 何点目・チーム・背番号・3P か FT か・ピリオド）
- 選手・コーチのファウルの並び（記号・フリースローの数・c・ピリオド）、退場・失格（5 個・GD）
- チームファウル（ピリオドごと。OT は第4Q に足す）、罰則の表示
- タイムアウト（ピリオド・残り・欄に書く分）、取れる残りの数、後半の最初の枠が使えなくなったか
- コート上の 5 人、出場した選手と最初に出たピリオド（出場の欄の × の色）
- ポゼッションアローの向き、今の攻撃のチーム（スタッツのとき）

この状態から、画面（得点板・選手のボタン）とスコアシート（2.5）を作る。

### 2.5 スコアシートの中身（`Scoresheet`）

公式の様式（`reference/kyoto_highschool_score_sheets_2020.pdf`、A4 縦）の欄に、そのまま対応させる。

| 欄 | 中身 |
| --- | --- |
| ヘッダー | チーム A・B、大会名・日付・時間・場所・ゲーム番号、クルーチーフ・アンパイア 1・2 |
| チーム欄（A・B） | タイムアウト（前半 2・後半 3・OT。枠ごとに分の数字か、使えなくなった枠の 2 本線）、チームファウル（クォーター①〜④ の 1〜4 に × を付ける）、選手 18 行（登録番号・氏名・背番号・出場（スターターは ×○、途中出場は × とその色）・ファウル 5 つ）、コーチ・A.コーチ |
| ランニングスコア | 1〜160 点。A・B の組が 4 列（1〜40、41〜80、81〜120、121〜160）。得点ごとに、点数の欄の印（2 点は斜線、3 点は斜線と背番号の○、1 点は塗りつぶした丸）と、外側の欄に背番号。ピリオドの終わりは最後の得点を太い○で囲んで下に線、試合の終わりは 2 本線 |
| 色 | 第1Q・第3Q は赤、第2Q・第4Q・OT は濃色（黒か濃い青） |
| 下の欄 | 各クォーター・OT の得点、最終スコア、勝者、試合終了時間、TO と審判の署名 |

画面の「スコアシート」と PDF は、同じ `Scoresheet` から描く。

## 3. 画面

### 3.1 画面の流れ

```
ホーム ─┬─ 新しい試合 → 試合の準備（4 段） → 記録 ─┬─ スコアシート（いつでも）
        │                                          ├─ 記録の一覧（Play by Play・修正）
        │                                          └─ 試合の終了 → 試合後（結果・分析・出力）
        ├─ 試合の一覧（すべて・未分類・大会ごと。6.1） → 試合後（または、試合中なら記録へ戻る）
        ├─ 大会のフォルダ（作る・名前を変える・消す・試合を移す）
        └─ チーム → チームの編集（選手・コーチ・種別の選択肢）
```

### 3.2 試合の準備（4 段）

1. **試合の情報**: 入れる大会のフォルダ（ホームで開いていた大会。その場で作れる）、大会名・日付・開始時刻・会場・ゲーム番号、審判と TO（空でよい）
2. **チーム**: A と B を名簿から選ぶ（その場で作ることもできる）。ベンチの位置（左右）
3. **出場登録とスターター**: チームごとに、名簿から出場する選手（18 人まで）とスターター 5 人を選ぶ。その試合だけの選手を足せる
4. **規則と記録の詳しさ**: 区分（一般・U18・U15・自由）、時計を使うか、詳しさ（公式・スタッツ・種別）、チームごとにスタッツを記録するか

### 3.3 記録の画面（タブレット横向き）

```
┌────────────────────────────────────────────────────────────────────────────┐
│ [≡]  2Q  07:43.0 [▶]   東西スターズ 34  -  31 南北   ◀アロー  [元に戻す] [シート] │
│      TF ×××□ | TO ●○      攻撃 A 0:12        TF ××××罰則 | TO ●●              │
├────────────────┬────────────────────────────────────────┬────────────────┤
│ チームA（ベンチ左）│                                        │ チームB（ベンチ右）│
│ ┌──┐┌──┐┌──┐      │      コートの図（スタッツのとき）           │      ┌──┐┌──┐┌──┐ │
│ │4 ││5 ││7 │      │      ・タップでシュートの位置              │      │7 ││10││11│ │
│ └──┘└──┘└──┘      │      ・攻める向きは前半・後半で入れ替え       │      └──┘└──┘└──┘ │
│ ┌──┐┌──┐          │                                        │          ┌──┐┌──┐ │
│ │8 ││12│          │      （公式のときは、選んだ選手に            │          │12││15│ │
│ └──┘└──┘          │        「1点・2点・3点・ファウル」を大きく）    │          └──┘└──┘ │
│ [交代][TO][チーム]  │                                        │  [交代][TO][チーム] │
├────────────────┴────────────────────────────────────────┴────────────────┤
│ 2Q 07:52  A #4 3P 成功（AST #5）  →  2Q 07:43  B #7 ファウル P1          [一覧] │
└────────────────────────────────────────────────────────────────────────────┘
```

操作の流れ:

- **公式**: 選手のボタン → 「1 点・2 点・3 点・ファウル」→（ファウルなら）記号とフリースローの数。2 タップか 3 タップ
- **スタッツ**: コートの図をタップ（位置）→ 成功 / 失敗 → 選手。続けて、成功ならアシスト、失敗ならリバウンドを聞く（飛ばせる）。フリースローはファウルのフリースローの数から続けて聞く
- 選手のボタン → 長押しで、その選手のファウル・リバウンド・ターンオーバー・スティール・ブロック・ディフレクション
- チームのボタン（[TO]・[交代]・[チーム]）: タイムアウト、交代（両チームまとめても可）、チームリバウンド・チームのターンオーバー、コーチ・ベンチのファウル
- 上の段: 時計のスタート / ストップ（大きなボタン。キーボードのスペースでも）、アローをタップで反転、[元に戻す]、[シート]（スコアシートを重ねて表示）
- 下の段: 直前の記録を 2 件。タップで修正、[一覧] で全部

知らせ（画面の中央に数秒）: 個人ファウルの 5 個目、GD、チームファウルの罰則、L2M に入った、タイムアウトの上限。

### 3.4 試合後と分析

タブで切り替える: 結果（各クォーターの得点・最終スコア・勝者）／スコアシート／ボックススコア／ゲームフロー／シュートチャートとヒートマップ／時間帯／アドバンスド／ラインナップ／種別／Play by Play。
右上に [PDF]・[CSV]・[共有]・[確定]。

## 5. 決めたこと（設計）

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 記録の持ち方 | 出来事の並び。状態と集計は毎回計算する | 修正・取り消しで食い違いが起きない。分析・動画・同期に使い回せる |
| 選手の情報 | 試合ごとに写しを持つ | 名簿を直しても、過去のスコアシートが変わらない |
| 出来事の保存形式 | Room の 1 行に JSON（kotlinx.serialization） | 型が増えても表を変えなくてよい |
| 画面の移動 | Navigation Compose | ほかのアプリと同じ |
| PDF | Android の `PdfDocument` に Canvas で描く | ライブラリを足さずに済み、A4 の座標で正確に描ける |
| 時計 | アプリが動いている間だけ進む（`SystemClock.elapsedRealtime` で計る）。止めたときの残りを保存する | アプリが落ちても、止まった時刻から再開できる |
| 時計の保存 | 試合ごとの残りを SharedPreferences に置く（止めたとき・動いている間は 5 秒ごと）。Room には入れない | 動いている間に何度も書くと、試合の画面が出来事の並びを読み直してしまう |
| 時刻の付け方 | 記録を足すときに、今の時計の残りを付ける。ピリオドの初めはその長さ、ピリオドの外（休み）の記録には付けない | 時間帯の分析と出場時間に使う。休みの記録は時間帯に入れない |
| 0:00 | 時計は 0:00 で止まり、ボタンが「次へ」になる。押すと確かめてから、ピリオドの終わりと次のピリオドの初めを記録する（第4Q 以降で同点でなければ試合を終える） | 審判の合図を待ってから進めるため、自動では進めない |
| 終わったピリオドのやり直し | 時計の修正で、終わったピリオドに時間を足すと、そのピリオドの終わりの記録を消して続きから記録する。終わりのあとに別の記録があれば、記録の一覧から直してもらう | 記録の並びを崩さない |
| 出場時間 | 交代と時計の残りから数える（時計を直した分も、そのまま時間に入る）。時計を使わない試合では数えない | 公式の出場時間は時計で決まるため |
| 攻撃時間（F-505） | 6 段目のポゼッションの判断と一緒に作る | 攻撃の切り替わりが決まらないと数えられない |
| シュートの位置 | 「右のゴールを攻める向き」にそろえた座標（0〜1）で持つ。左のゴールを攻めたシュートは 180 度回す | シューターから見た左右（左コーナー・右コーナー）を保ったまま、前半と後半のシュートを 1 枚のチャートに重ねられる |
| 2P / 3P の自動判断 | FIBA の寸法（半径 6.75 m の弧と、サイドラインから 0.9 m のコーナーの直線）で判断し、チップで直せる | 審判の合図に合わせて変えられるようにする（F-401） |
| スタッツの入力の順番 | 位置・成否・選手の 3 つがそろったら記録する。先に選手を選んでいれば、その選手のシュートにする | どの順番でも入れられる（F-401） |
| 続けて聞くこと | 成功ならアシスト、失敗ならリバウンドとブロック、フリースローのあるファウルならフリースロー（打つ人と成否）。選手のボタンでも答えられ、関係のない選手を押すと問いかけを閉じる | 記録の手数を減らし、飛ばしても困らないようにする |
| ポゼッション | 記録から自動で判断し、食い違ったら記録したチームが攻めていたとみなして直す。得点板の「攻撃」を押すと手で入れ替える（PossessionChange） | オフェンスリバウンドで攻撃は続く。記録の漏れがあっても、次の記録で正しい向きに戻る |

## 6. 1.0 のあとに足したもの

### 6.1 大会ごとのフォルダ（F-1007、2026-11-13）

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| データ | `folder` の表（名前・作成日時）と、`game.folder_id`（null なら未分類）。データベースの版 3 で、Room の自動の移行（表と列の追加だけ）で足す | 1 試合は 1 つの大会に入る。今の試合は、そのまま未分類になる |
| 外部キー | `game.folder_id` には付けない。フォルダを消すときは、同じトランザクションの中で試合の folder_id を null に戻してから消す | 外部キーを足すと `game` の表を作り直す移行になり、その途中で表を消すと、外部キー（CASCADE）で出来事まで消える恐れがある |
| ホームの形 | 幅が 840dp 以上（タブレットの横向き）なら、左に「すべての試合・未分類・大会の一覧」、右にその試合。狭い画面では、上のボタンで大会を選ぶ | 大会が増えても一覧で見渡せる。ほかの画面から戻っても、開いていた大会を覚えておく |
| 大会の並び | 中の試合の最後の日付（試合が無ければ作った日）の新しい順 | 今の大会と、これから行う大会（作ったばかりで試合が無い）が上に来る |
| 大会の名前 | 空と、ほかの大会と同じ名前は受け付けない | 移す先を選ぶときに取り違えない |
| 大会名（ヘッダー）との関係 | 大会を開いて作った試合は、その大会に入り、大会名が空ならフォルダの名前を入れる。準備の画面でフォルダを選び直すと、大会名が前のフォルダの名前のままなら一緒に変える。フォルダの名前を変えても、移しても、試合の大会名（スコアシートに載る）は変えない | スコアシートは公式の記録なので、整理の操作で書き換えない |
| 試合を移す | 各試合の行の移すボタン（1 試合）と、メニューの「試合をまとめて大会に移す」（見ている大会の試合から選ぶ）。移す先は未分類・大会・新しい大会。確定した試合も移せる | 移しても記録は変わらない。前に作った試合も、あとから整理できる |
| まとめて消す | 見ている大会（すべて・未分類・大会）の試合から選ぶ | 大会を丸ごと片付けられる |
| フォルダを消す | 中の試合は消さずに未分類へ戻す。試合も消すときは、先に「まとめて消す」で消す | 誤って記録を消さない |
| バックアップ | 形式を 2 にし、大会の一覧と試合の folder_id を入れる。形式 1 のファイルは、全試合を未分類として読む。ファイルの中に無い大会を指す試合は未分類にする | 古いバックアップも戻せる。古い版のアプリは形式 2 を読まない（大会を落として戻さない） |
