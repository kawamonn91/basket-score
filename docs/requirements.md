# バスケットボール スコアシート アプリ 要件定義書

- 版: 第3版（2026-11-12。第2版で Basket Plus と同じ機能を足し、第3版でアプリ名・価格などを決めた）
- アプリ名: **Basket Score**（パッケージ名 `com.ttech.basketscore`、リポジトリ `kawamonn91/basket-score`（公開）、フォルダ `C:\dev\basket-score`）
- 状態: 要件定義が固まった。次は画面設計と実装計画

## 1. 目的

バスケットボールの試合を Android タブレットで記録し、分析・共有するアプリを作る。

- 大会のテーブルオフィシャルズ（TO）のスコアラーとして、JBA の公式スコアシートと同じ項目・記号で記録し、公式と同じ並びの PDF を出す
- 自分のチームの試合では、公式のスコアシートには無い記録（リバウンド・アシスト・ブロック・スティール・ターンオーバー、シュートの位置と成否、時刻など）も残し、試合後や複数の試合にまたがって、選手ごと・時間帯ごと・5 人の組み合わせごとに分析する
- **Basket Plus（https://basket-plus.jp/ 、iPad 用）でできることは、すべてできるようにする**（6 章の対応表）。ただし、画面・デザイン・名前・図柄は写さず、機能だけを満たすように独自に作る

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| TO | テーブルオフィシャルズ（スコアラー・アシスタントスコアラー・タイマー・ショットクロックオペレーター） |
| Q / OT | クォーター / オーバータイム（延長） |
| L2M | 第4Q と各 OT の残り 2:00 以下（Last 2 Minutes） |
| ランニングスコア | 得点のたびに、累計の点数の欄に得点者の番号と記号を書いていく欄 |
| チームファウル | クォーターごとのチームのファウル数。4 個を超えると罰則（5 個目からフリースロー） |
| 記録（イベント） | 得点・ファウル・タイムアウト・交代・リバウンドなど、試合中に入力する 1 つ 1 つの出来事 |
| ポゼッション（攻撃回数） | 一方のチームがボールを持ってから、相手に渡るまでの 1 回の攻撃 |
| ラインナップ | コート上の 5 人の組み合わせ |
| Play by Play | 記録を時刻の順に並べたもの。動画と組み合わせて、その場面を再生する |

## 4. 利用場面と記録の詳しさ

試合ごとに「記録の詳しさ」を選ぶ。途中で上げ下げしてもよい（それまでの記録は消えない）。

| 詳しさ | 入力するもの | 想定する場面 |
| --- | --- | --- |
| 公式 | 得点・ファウル・タイムアウト・出場（交代）・ポゼッションアロー | 大会の TO。公式のスコアシートと同じだけを速く入力する |
| 公式＋スタッツ | 上に加えて、シュートの位置と成否（外れも）・リバウンド・アシスト・ブロック・スティール・ターンオーバー・ディフレクション | 自分のチームの試合の記録 |
| 公式＋スタッツ＋種別 | 上に加えて、プレーの種別（オフェンス・ディフェンス・シュート・スティール・ターンオーバーの種類） | 詳しく分析したい試合（記録の担当を 1 人置ける場合） |

- スタッツは、チームごとに「記録する / しない」を選べる（自分のチームだけ詳しく、相手は公式の項目だけ、など）
- 公式の項目は、どの詳しさでも同じ規則で記録し、同じ PDF が出る

## 8. 画面

タブレットの横向きを基本にする。スマホは、1.0 では端末の中の試合と PDF を見るだけ。2.0 からクラウドの閲覧画面になる。

| 画面 | 中身 |
| --- | --- |
| ホーム | 試合の一覧、新しい試合、チームの管理、集計、作戦ボード |
| チームの管理 | チーム・選手・コーチの登録、チームのコピー、種別の選択肢 |
| 試合の準備 | ヘッダー・審判と TO・区分と規則・出場登録・スターティングファイブ・ベンチの位置・記録の詳しさ |
| 記録（試合中） | 下の図 |
| スコアシート | 公式の並びの表示（試合中でも見られる）と PDF の出力 |
| 分析 | ボックススコア・ゲームフロー・シュートチャート・ヒートマップ・時間帯・アドバンスド・ラインナップ・種別・Play by Play |
| 集計 | 期間・試合・メンバーを指定した集計 |
| 作戦ボード | コートの図に選手と線を置く |

記録の画面（タブレット横向き）のおおまかな並び:

```
┌────────────────────────────────────────────────────────────────────┐
│ 2Q  07:43 [▶/■]   A 東西スターズ 34 - 31 南北 B   ◀ アロー  [ミニBS] │
│ TF A:3 / B:4(ペナルティ)   TO A:●○ / B:●●   攻撃: A 0:12              │
├───────────────┬──────────────────────────────────┬───────────────┤
│ チームA        │                                  │ チームB        │
│ (コート上の5人) │   コートの図（フルコート）          │ (コート上の5人) │
│ [4] 静岡 P2    │   タップでシュートの位置             │ [7] … P1      │
│ [5] …         │   （攻める向きは前半・後半で入れ替え）│ [10] …        │
│ ベンチ ▼      │                                  │ ベンチ ▼      │
│ [交代] [TO]    │ [成功][失敗][FT][ファウル][REB][AST]│ [交代] [TO]   │
│               │ [STL][BLK][TOV][DEF][種別][両交代] │               │
├───────────────┴──────────────────────────────────┴───────────────┤
│ 直前の記録: 2Q 07:52 A #4 3P 成功（AST #5・セット）  [元に戻す] [一覧] │
└────────────────────────────────────────────────────────────────────┘
```

- チーム A・B の左右はベンチの位置に合わせ、後半も入れ替えない（F-409）
- 「公式」の詳しさのときは、コートの図とスタッツのボタンを隠し、選手のボタンと「1 点・2 点・3 点・ファウル」を大きくする
- 選手のボタンには背番号・名前・ファウル数を出す（5 個目が近い選手は色を変える）

## 9. 非機能要件

| 項目 | 要件 |
| --- | --- |
| 通信 | 1.0・1.1 は通信しない（インターネットの権限を持たない）。体育館の電波が悪くても全機能が使える。2.0 からは、送るのは電波があるときだけで、記録はいつも端末で完結する |
| 速さ | 1 つの記録は 3 タップ以内。ボタンを押してから反映まで体感で待たない（0.1 秒以内）。1 試合の分析の表示は 1 秒以内 |
| 誤操作 | 取り消しはいつでも 1 タップ。試合を終える・記録を消すときは確認を出す |
| 保存 | 操作のたびに保存（F-1002）。記録は「出来事の並び」として持ち、スコアシート・集計・分析はそこから毎回作る（修正・取り消しで食い違いが起きない。動画との連動もこの並びを使う） |
| 端末 | Android 8.0（API 26）以上。10 インチ前後のタブレットの横向きを基本に、7〜8 インチも崩れない |
| 試合中の画面 | 画面を消さない。通知や戻る操作で試合を誤って抜けない |
| 見た目 | 体育館の明るさで見やすい配色。チームの色を画面に反映する。ダークテーマにも対応 |
| 言語 | 日本語 |
| データの量 | 1 試合の記録はおよそ 300〜1500 件（種別まで付けると多い）。数百試合を保存しても一覧と集計がすぐ出る |
| 個人情報（2.0 から） | 選手の氏名・顔写真は未成年のものを含む。サーバーとの通信は暗号化し、閲覧は招待した人だけ。チームがデータを消せる。プライバシーポリシーを用意する |

## 12. 進め方（案）

1. リポジトリを作り、アプリのひな形・CI・CD を入れる（2026-11-12）
2. 画面設計: 記録の画面の操作の流れを、紙で 1 試合分なぞって確かめる。公式のスコアシートの PDF の並びを決める
3. 実装計画: Kotlin・Jetpack Compose・Room。記録は出来事の並びで保存。分析は出来事の並びから計算する純粋な関数にして、単体テストで指標を確かめる。PDF は Android の PdfDocument で描く
4. 1.0 の実装の順番: ① 公式の記録とスコアシートの PDF → ② タイマーとスタッツ・シュートの位置 → ③ 分析（ボックススコア・ゲームフロー・シュートチャート → アドバンスド・ラインナップ・種別・時間帯）→ ④ CSV・バックアップ
5. CI と CD は最初の PR で入れる（`C:\dev\CLAUDE.md` の決まり）。T-tech Store に出すときはスクリーンショットも撮る
6. 1.1・2.0・3.0 は、1.0 を実際の試合で使ってから順に

## 付録 A. 指標の定義

Basket Plus の計算式は公開されていないため、一般的な定義を使う。アプリの「指標の説明」画面にも同じ式を出す。

| 指標 | 式 |
| --- | --- |
| FG% | FGM ÷ FGA（FGM・FGA は 2P と 3P の成功数・試投数の合計） |
| eFG%（EFG） | (FGM + 0.5 × 3PM) ÷ FGA |
| 攻撃回数（ポゼッション） | 記録から数えた実際の回数（F-411）。記録が足りない試合は FGA + 0.44 × FTA − OR + TO で推定する |
| PACE | 攻撃回数 ÷ 試合の分 × 40（10 分の Q の場合。区分の試合時間に合わせる） |
| 得点効率（PPP） | 得点 ÷ 攻撃回数 |
| TO%（TO 率） | TO ÷ (FGA + 0.44 × FTA + TO) |
| FTR | FTA ÷ FGA |
| ORB% | OR ÷ (OR + 相手の DR) |
| FTM / PTS | フリースローの成功数 ÷ 得点 |
| AST Rate | AST ÷ FGM |
| EFF（貢献度） | 得点 + リバウンド + アシスト + スティール + ブロック − (FGA − FGM) − (FTA − FTM) − TO |
| +/- | その選手がコートにいた間の、チームの得点 − 相手の得点 |
| 期待値 | エリア（または種別）ごとの、シュート 1 本あたりの得点（そのエリアの得点 ÷ 試投数） |
| セカンドチャンスポイント | オフェンスリバウンドで続いた攻撃での得点 |
| TO からの得点 | 相手のターンオーバーで始まった攻撃での得点 |
| 単位時間換算 | 値 ÷ 出場時間（分）× 30 |
